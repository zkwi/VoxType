# VoxType 0.14.1 Tauri 2.12 与依赖维护发布审计

日期：2026-10-01

## 版本判断

本次从 `0.14.0` 升到 `0.14.1`。内容是依赖升级、一处随升级必须跟着改的规避修正和一处死配置清理，没有新功能，也没有用户可见的行为或默认策略变化，按项目版本策略递增 patch。

## 用户问题与本轮范围

0.14.0 发布后，Dependabot 按新的分组配置重新提了 5 个 PR，另有 #46 登记的四项破坏性依赖升级没有做。用户要求把 GitHub 上的 issue 和 PR 全部处理掉，由 AI 自行审计，然后发布新版本并更新本机运行的版本。

范围只包括依赖和与之直接相关的改动。0.14.0 审计里列出的其他后续项（屏幕 OCR 等待上限、鼠标钩子按需安装等）不在本轮。

## 改动与依据

### Tauri 2.12 必须和 `windows 0.62` 一起升

0.14.0 审计预计 Tauri 两侧的 PR 会因为 CLI 的主次版本一致性校验而各自失败。实际结果更具体：

- npm 一侧（#57）确实败在 Tauri 调试构建上。
- Rust 一侧（#56）败得更早，在 `cargo check`：Tauri 2.12 改用 `windows 0.62`，`window.hwnd()` 返回的是 0.62 的 `HWND`，而项目直接依赖的还是 `windows 0.61`，`overlay.rs` 里把它传给自己的 Win32 调用时类型对不上。

所以 Tauri 的次版本升级除了两侧要合成一个 PR，还必须把项目的 `windows` 依赖升到 Tauri 所用的版本。Dependabot 配置和注释已按这个结论更新：`windows` 的忽略规则保留，理由改为“只跟着 Tauri 的次版本一起手工升级”。

升到 `windows 0.62` 之后，代码侧只有一处编译错误：WinRT 异步操作的阻塞等待由 `get()` 改名为 `join()`，实现等价，只影响屏幕 OCR 等待识别结果的那一行。

### 托盘定时器规避差点随升级失效

0.14.0 加的规避依赖托盘库 `tray-icon` 的两个内部常量。这次升级把 `tray-icon` 从 0.24.1 带到 0.25.1，核对新版源码发现：

- 窗口类名没变。
- “鼠标离开图标”定时器的编号从 `6008` 变成了 `6007`（前面删掉了一个内部消息编号，后面的整体前移）。
- 缺陷本身没有修。上游已有对应的 issue [tauri-apps/tray-icon#292](https://github.com/tauri-apps/tray-icon/issues/292) 和修复 PR [#371](https://github.com/tauri-apps/tray-icon/pull/371)，改法与 0.14.0 审计里的诊断一致，但还没有合并。因此没有再向上游重复提 issue。

如果只升级不改，规避会去停一个不存在的定时器，主线程常驻空转的问题会原样回来，而且没有任何报错。现在改为把 `6000-6031` 整段都停一遍：托盘窗口上只有这一个定时器，区间里不存在的编号只是停表失败，没有副作用。单测断言两个已知版本的编号都落在区间内。

### `toml 1.x` 与 `tokio-tungstenite 0.30`

两者代码都无需改动。

- `toml`：项目只用 `from_str` 和 `to_string_pretty`。用一个临时探针对示例配置、已安装版本的配置和开发用配置三份真实文件做“解析后重新序列化”的指纹对比，0.9.12、1.1.2、1.1.3 三个版本下输出的长度、行数和哈希完全相同，再次序列化也稳定。探针只打印长度和哈希，没有提交。
- `tokio-tungstenite`：上游 0.30 的变化只有服务端握手校验更严格、依赖更新和 MSRV 提高，VoxType 只作为客户端使用。

### `cpal` 暂不升级

试过直接升到 0.18.2。编译错误只有两类共 8 处，但行为上有两处变化不能机械带过：

- Windows 上设备名称的来源从 `DeviceDesc` 改成 `FriendlyName`。VoxType 按名称保存用户选择的麦克风，后端和设置页都按名称匹配，升级后旧名称对不上，会每次录音都提示“回退默认输入设备”。
- 从 0.18.2 起，采集出现不连续时会通过错误回调上报，而 VoxType 把任何流错误都当作致命错误。机械升级之后，录音中的一次小卡顿就会让整次输入失败；0.17 下这类不连续一直是被忽略、输入照常成功的。

这两处都需要先定策略，并且只能靠真实麦克风验证。`cpal 0.17.3` 目前没有安全公告，0.18 也没有 VoxType 必需的能力，所以按用户确认的推荐方案暂不升级：Dependabot 继续忽略它的次版本和大版本，分析、迁移清单和真机回归步骤留在 #46，需要时重开。

### 权限声明清理

核对 Tauri 2.12 的权限相关修复时发现，`capabilities/default.json` 的窗口列表里还有 `startup-toast`。这个启动提示窗在 0.14.0 已经删除，全仓库没有其他引用。给不存在的窗口标签授权是死配置，以后若有同名窗口还会自动拿到这些权限，已删除。

## 自查审计

用户明确要求由 AI 自行审计，所以本次没有另做独立复审。自查内容和结论：

- **差异**：`v0.14.0` 之后的代码改动只有三处：`tray.rs` 的定时器编号区间、`screen_context.rs` 的 `join()`、权限声明。其余是清单文件、锁文件、配置和文档。
- **上游更新日志**：逐条看了 Tauri 2.12.0 和 2.12.1、`wry 0.57`、`plugin-opener`、`plugin-single-instance`、`tungstenite 0.30` 和 `cpal 0.18` 的更新日志。Tauri 2.12 对 Windows 桌面端没有破坏性变化；它去掉了对 Windows 7 的支持，VoxType 本来只面向 Windows 10 和 11。
- **安全**：Tauri 2.12 修复 GHSA-w28w-mhc8-qvjv（IPC 通道数据可能被同一应用的其他 webview 读到）。VoxType 的两个窗口都只加载本地页面，实际影响很低。`cargo audit` 里两条已登记的 `quick-xml` 公告在 Tauri 2.12 下仍然存在（仍经由 `plist 1.9.0` 引入），忽略项保留，注释里的版本号已更新。GitHub 上 Dependabot、代码扫描、密钥扫描的未关闭告警均为 0。
- **权限**：Tauri 2.12 调整了“拒绝”类权限的作用范围。VoxType 的权限声明里没有任何拒绝规则，不受影响。
- **主链路**：没有改动主链路代码。变化在底层绑定：`windows` 覆盖剪贴板、热键与输入钩子、屏幕 OCR、系统音量和悬浮窗置顶，`tokio-tungstenite` 覆盖 ASR 会话。这些靠编译、单测、真实剪贴板手工回归和真实应用核对覆盖，具体见“验证”。
- **隐私**：没有新增日志或数据留存。

- 新增单测：托盘定时器按编号区间清理（区间内的编号能停掉、区间外和类名不符的不受影响），以及两个已知 `tray-icon` 版本的编号都在区间内。
- GitHub 上 #61、#62 各自的 10 项检查全部通过后才合并。

### 真实系统剪贴板（手工回归，本机执行）

在 `windows 0.62.2` 下执行 `cargo test --lib real_clipboard -- --ignored --nocapture --test-threads=1`，两条均通过：独占打开拒绝另一线程的 `OpenClipboard(NULL)`；恢复 `CF_DIB` 后 `CF_BITMAP` 由系统重新合成。这是 `windows` 升级影响最大的一块代码。

## 已知差异与后续项

- 本版换了窗口层和 Win32 绑定的版本。右 Alt 的听写已有一次真实使用佐证，其余触发方式和托盘操作还没有。如果之后出现问题，可以用 0.14.0 的安装包覆盖安装回退，配置和统计文件不受影响。
- `cpal 0.18` 的迁移暂不计划，见 #46。
- 托盘定时器的规避要等上游修复随 Tauri 升级进来之后才能删除。
- 0.14.0 审计里的其余后续项没有变化：屏幕 OCR 等待上限的取舍、字幕窗独立轻量入口、渲染进程内存的长期复查、鼠标钩子按需安装。

## 手工回归建议

需要真实按键和麦克风，无法由 AI 自测：

1. 用 Ctrl + Q 完成一次“说话 → 停止 → 粘贴”，确认文本正确、原剪贴板内容恢复。右 Alt 已有一次真实使用佐证；主快捷键走的是另一套注册方式（全局热键而不是输入钩子），本版换了 `windows` 绑定之后还没有真实按过。
2. 用鼠标点击托盘图标打开主窗口，再关回托盘；几秒后日志里出现“已停止托盘图标残留的鼠标离开检测定时器”，说明新版托盘库下规避仍然生效。
3. 在托盘菜单里逐项点一遍（打开配置、查看日志、检查更新、重启程序），确认新版菜单库下行为正常。
